# Package review

The initial review covered the public C ABI, GenTL loading and ownership, GenApi port and feature access, stream control, receive and release, tests, diagnostics, and CMake build and installation. Review validation used software fixtures.

## Findings

| ID | Severity and confidence | Evidence and effect | Remediation and validation |
| --- | --- | --- | --- |
| GRAB-01 | High, confirmed cleanup path | `Producer::~Producer` ignores error statuses from interface, system and library close, then calls `dlclose`. The exception path already recognizes that a failed close can leave live CTI resources. A returned failure can produce the same hazard. See [producer.cpp](src/producer.cpp). | Preserve the module and represent unfinished teardown as retryable ownership. Inject failures at each layer and verify release order and unload. |
| GRAB-02 | High, confirmed contract mismatch | Receive takes the stream mutex after the initial try-lock, the reader destructor takes it again, and poll uses the blocking release path. A concurrent holder can therefore block try or poll after entry despite the public consumer-lock guarantee. See [frame.cpp](src/frame.cpp) and [iris.h](inc/iris.h). | Define which calls may contend and redesign the state transition or narrow the guarantee. Add a deterministic race test that holds the required mutex after receive begins. |
| GRAB-03 | High, confirmed rollback gap | A throw from `DSStartAcquisition` bypasses the grabbing-state check. A negative return with an unavailable grabbing query also leaves `host` false. Rollback can attempt event removal and buffer revocation without establishing that the data stream stopped. See [stream.cpp](src/stream.cpp). | Track uncertain start state and attempt host stop before revoking. Inject a start that arms acquisition and then throws or returns an error while the grabbing query fails. |
| GRAB-04 | Medium, confirmed ownership gap | Device open acquires an interface reference before refresh and open. It releases that reference on an error return, while a thrown producer exception bypasses the release. A sibling device can keep the producer alive with the extra reference. The interface table also inserts a record before calling a producer function that can throw. See [device.cpp](src/device.cpp) and [producer.cpp](src/producer.cpp). | Make acquisition and rollback cover both error returns and throws. Test an open failure while another device holds the producer. |
| GRAB-05 | Medium, confirmed sharing gap | System and interface handles are shared, but their node maps are cached per device. Two views can retain different cache state, and independent event subscriptions can conflict on the same port. The feature lock serializes calls but does not share cache ownership. See [node_map.cpp](src/node_map.cpp). | Give each shared port one node map and subscription, or explicitly define separate cache and subscription semantics. Exercise two devices on one interface. |
| GRAB-06 | Medium, confirmed missing validation | Image validation derives row size from the format code's occupied bits without format-specific packing validation. It also does not compare an available delivered height against nominal height when filled bytes suffice. The short-image guard covers observed truncation, but there are no packed-format or contradictory-metadata fixtures. See [frame.cpp](src/frame.cpp). | Define supported layout rules and test packed formats, delivered height, padding and malformed metadata with a fixture. |
| GRAB-07 | Medium, confirmed test scope | The numeric-list tests exercise the production copy path with typed list-producing doubles. The shipped EMVA XML schema marks the integer list declaration unsupported and has no float equivalent. Successful list queries through an EMVA-loaded XML map remain unverified. See [feature_values.cpp](tests/feature_values.cpp) and the [GenApi standard](https://www.emva.org/wp-content/uploads/GenICam_Standard_v2_1_1.pdf). | Qualify a real GenApi implementation or fixture that provides list-valued nodes before promising this end-to-end behavior. Keep the existing fixed-increment rejection tests. |
| GRAB-08 | Low, confirmed API gap | `IRIS_DISCONNECTED` is declared but no producer status path returns it. See [iris.h](inc/iris.h) and [producer.cpp](src/producer.cpp). | Specify observable disconnect signals and the status mapping or document the value as reserved. |

The invalidation work adds explicit subscribe and bounded poll calls. The register-backed fixture proves that a producer-side update leaves a cached constraint stale until its event is consumed. continuous simulator exercises the same consumer API against its GenTL event implementation. Event polling uses the feature lock and can allocate. Frame receipt and requeue remain on the separate capture path.

The installed library exports the public C functions and depends on the GenApi runtime through the documented loader setup. The installed capture tool includes glibc allocator interception for the bench. Its observations describe intercepted calls and caller attribution on the tested platform. Hardware compatibility and vendor failure containment remain qualification topics outside these software results.

## Verification

Four release CTest tests passed. The coverage target passed with 93.5% line coverage (865 of 925), 100% function coverage and 54.8% branch coverage. C11 and C++17 header checks and CMake installation passed. The mixed fixture used triggered mock and continuous simulator. The findings below record the subsequent disposition.

## High-priority remediation

- **GRAB-01 fixed.** Last-device close preserves the producer and retries the unfinished teardown stage. Failed discovery teardown retains the producer in the registry for retry before a subsequent load. Fault tests inject interface, system, and library close failures, check that the module stays loaded, retry close, and check that it unloads.
- **GRAB-02 fixed.** Try and bounded poll take the stream mutex once with try-lock. An admitted call holds it through producer calls, frame publication, and inline callback/requeue. This trades concurrent control access for a single lock acquisition with no consumer-lock wait in try or poll. The contention fixture checks that a competing reader gets BUSY while a callback has a completed frame. Blocking wait still drops the lock for the producer wait, allowing stop to cancel it.
- **GRAB-03 fixed.** Startup records possible host acquisition before invoking the CTI. Failure and exception paths preserve that ownership unless the producer confirms that acquisition is idle. Fault tests arm the stream, fail or throw, withhold the grabbing status, and reject the first stop. The fixture aborts if the consumer unregisters events, flushes, or revokes while armed.

Five release tests passed three consecutive runs. The mixed triggered mock and continuous simulator test measured zero heap allocations attributed to the consumer in all capture intervals. The coverage gate passed at 93.0% line coverage (909 of 977). Physical cameras were outside this verification. See the follow-up below for GRAB-04 through GRAB-08.

## Remaining findings remediation

- **GRAB-04 fixed.** Failed opens relinquish the interface reference on both exception and error paths. A partially returned device handle stays attached to its interface until close succeeds. The fault CTI throws after returning a second device handle while a peer remains open, then verifies device cleanup, interface close, and module unload. A separate fault throws from interface open.
- **GRAB-05 fixed.** The producer and interface records own their respective node maps and subscriptions. Two simulated devices check identity, shared readback, idempotent subscription, and continued use after one device closes.
- **GRAB-06 fixed.** Frame validation now accepts explicitly supported single-plane formats and whole-row packed Mono groups. The fixtures cover a packed image with offset and padding, a partial packing group, and reported heights below and above the nominal height even when byte count is sufficient. [PFNC 2.4](https://www.emva.org/wp-content/uploads/GenICam_PFNC_2_4.pdf)
- **GRAB-07 fixed.** EMVA GenApi 3.5.1 exposes list mode for a semicolon-separated integer ValidValueSet. A Converter exposes that list as floats. Both types are now tested through the XML-loaded node map and public C API for size query, insufficient capacity, and exact values. Fixed-increment rejection is also tested.
- **GRAB-08 resolved as reserved.** GenTL I/O failure alone does not establish a device disconnect. The public header reserves IRIS_DISCONNECTED, and a simulated I/O event verifies the existing generic producer status and preserved native code.

The independent reviewer found a diagnostic lifetime mismatch on successful calls that suppress an optional internal probe failure. The public contract now requires reading diagnostics immediately after a negative return and copying strings before another library call. The failed-open regressions check diagnostics at that boundary.

Five simulator tests passed three consecutive release runs. Line coverage was 93.2% (1,004 of 1,077). The mixed release test reported zero heap allocations attributed to the consumer. Strict C11 and C++17 header checks passed, and all 46 public exports matched the header. No remaining blocker was found for freezing the Linux x86-64 C ABI on this simulator evidence. The header remains draft pending the release decision. Hardware and Julia were outside this pass.

The first Iris GenTL snapshot used a frozen Linux x86-64 C ABI baseline and exact-match CTest checks. The release build passed all seven tests, and the coverage gate remained at 93.2%. Temporary negative checks rejected changes to a signature, a status value, struct packing, and the ELF exports, version node, and SONAME. The project subsequently resumed development with a provisional C API and ABI and retired those exact-match checks.

## Independent review of payload views

The independent review covered GenTL buffer and chunk offsets, GenDC descriptor and part bounds, and validity while the consumer holds a frame. The fixes and simulator regressions are recorded below.

| ID | Finding | Disposition |
| --- | --- | --- |
| GRAB-15 | High, confirmed. A duplicate producer completion could overwrite descriptors held by the application. | Receive checks the borrow under the stream lock before reading completion metadata. The duplicate fixture checks the original descriptors through stop and enforces release before close. |
| GRAB-16 | Medium, confirmed. Treating bytes filled as an end offset rejected gapped multipart and GenDC layouts and attached chunks. | Validate physical ranges against the announced extent and producer-reported capacity. Budget used bytes independently when filled size is reported. Regressions cover gapped layouts, omitted filled size, overlaps, and chunk-only multipart. |
| GRAB-17 | Medium, confirmed. Structured views could read preliminary GenDC descriptors or buffers without a confirmed completion status. Custom GenDC types could be parsed using an unrelated header layout. | Require complete status and a final GenDC descriptor. Check part and header ranges before decoding format-specific fields. Regressions cover omitted completion status, preliminary descriptors, aliased headers, and a custom part without a standard dimension block. |
| GRAB-18 | Medium, confirmed. A chunk-marked embedded GenDC XML part could supersede remote XML used for named lookup. | Keep the bounded part views and decline named decoding for that layout. Regression checks both parts and the explicit unsupported status. |
| GRAB-19 | Medium, confirmed on re-review. Duplicate chunk IDs could produce an ambiguous named read. Transport chunk descriptors could overlap, and a truncated H.264 part header could be accepted. | Reject duplicate IDs in both layouts, overlapping transport chunk ranges, and H.264 headers shorter than the standard header. Added simulator regressions for all three. |

References for GRAB-16 through GRAB-19 are [GenTL 1.6](https://www.emva.org/wp-content/uploads/GenICam_GenTL_1_6.pdf) and [GenDC 1.2](https://www.emva.org/wp-content/uploads/GenICam_GenDC_v1_2.pdf).

## Independent review of GenApi additions

The independent pass reviewed named metadata and registers, XML loading, ordered writes, module events, feature invalidation, and chunk access against the current source. All findings below were remediated in the existing workspace on `main` at source commit `51d7c3e`. The workspace already contained the uncommitted GenApi and acquisition changes.

| ID | Finding | Disposition |
| --- | --- | --- |
| GRAB-20 | High, reproduced. Remote feature invalidation was registered only on the remote port. After adding the standard source, a notification naming a derived feature could still leave its backing register cached. | Try the local device handle first and fall back to the remote port if the producer rejects the source. Unregister on the handle that registered. Invalidate the whole map for a known notification so cached registers across selector states refresh without writes to the device. The fault CTI requires the local handle and names a derived node. continuous simulator exercises the remote-port fallback. |
| GRAB-21 | Medium, confirmed. A failed feature-invalidation registration could leave a producer handle published and untracked. | Retain the partial handle, roll back, and preserve the registration diagnostic. The fixture reports a registration error after publishing a handle and rejects the first unregistration. Owner close retries cleanup. |
| GRAB-22 | Medium, reproduced. The port bridge reported writable access even when the producer reported a read-only port opened in control mode. | Use GenTL port access information when available, capped by the open mode. The fixture verifies read-only metadata and rejects a register write before it reaches the producer. |
| GRAB-23 | Medium, reproduced. A successful producer text query could be parsed past its reported byte count. | Validate the reported size and require a terminator within that extent. The invalidation regression verifies a truncated returned name fails after consuming its event. |
| GRAB-24 | Medium, reproduced. A runtime event envelope over the buffer cap remained at the queue head and blocked later events indefinitely. | Share bounded envelope handling across device, module, and invalidation events. Discard the oversized head under the feature lock and report the error. The next poll reaches a valid event. |
| GRAB-25 | Medium, reproduced. For a complete contiguous image or chunk payload, a descriptor could reference capacity beyond the producer's `DATA_SIZE` when `SIZE_FILLED` was unavailable. | Use `DATA_SIZE` as a secondary bound for those payload types. Regressions exercise a valid descriptor and an out-of-extent descriptor with no reported filled count. |

GenTL source, registration, event queue, and buffer semantics are described in [GenTL 1.6, §§4.2, 6.3.7.2, and 6.4.4.4](https://www.emva.org/wp-content/uploads/GenICam_GenTL_1_6.pdf). Iris's supported capabilities are recorded in [API_REVIEW.md](API_REVIEW.md#implemented-gentl-and-genapi-capabilities).

## Public preview review

- **Producer lifetime.** Different canonical paths can resolve to the same loaded CTI object. A hard-link regression reproduced double initialization and an abort at device close. Iris now shares the producer lifetime for the same loader handle and rejects an alias open while another owner still has cleanup pending.
- **Stream startup.** Successful new-buffer event registration must return an event handle. Iris now reports a producer error before queueing or starting acquisition if the handle is missing. It unregisters any successful registration and retains pending cleanup for retry. The regression injects a null event handle and one unregister failure, then verifies that a subsequent start succeeds.
- **Release scope.** The preview targets Linux x86-64 with glibc. The public archive contains Iris source under MIT, with separate, locally obtained GenApi and CTI dependencies.

The release, coverage, and UBSan builds passed all 16 software tests. Consumer line coverage was 96.3% (2,302 of 2,390). Concurrent simulator capture with caller-owned buffers delivered 1,585 triggered mock and 50 continuous simulator frames with zero Iris heap calls or bytes. The release install passed C11 and C++17 client linkage and execution, and all 85 public declarations matched the installed exports. Doxygen completed without warnings.
