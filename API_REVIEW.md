# GenTL consumer C API review

[iris.h](inc/iris.h) defines the Linux x86-64 C ABI for complete-frame acquisition. C, C++ and Julia can use the same library. The public handle hierarchy follows GenTL, feature names and types follow GenApi and SFNC, and buffer delivery uses the GenTL announced-buffer queue.

## API review

1. **Producer and device lifetime.** A single context can acquire from devices on several CTIs at once. Canonicalize CTI paths and coordinate initialization process-wide within the consumer. Keep dispatch tables, interface IDs and device IDs scoped to their producer. Keep registry operations off the frame path. Reference-count producer and interface handles across open devices. A discovery refresh must not close an interface another device owns. Handle missing or duplicate serials explicitly, keep exact IDs as the reopen mechanism, and do not silently select a different producer. Applications can compose discovery across producers from explicit scans.
2. **Node maps and feature access.** Load module XML via GenTL port URL information, with the older URL function where needed. Handle register-backed XML and ZIP and approved file URLs. Bridge reads and writes through the module's port and detect short transfers. Serialize feature access across maps sharing a port and preserve order for selector-dependent operations. Query enum entry access and numeric constraints at use time. Test GenApi cache behavior with selector changes and producer-driven updates. If a required feature needs event-based invalidation, qualify that producer before relying on it. Numeric units come from the feature, including microseconds for SFNC `ExposureTime`. Text conversions use GenApi semantics. [GenTL 1.6](https://www.emva.org/wp-content/uploads/GenICam_GenTL_1_6.pdf) · [GenApi 2.1.1](https://www.emva.org/wp-content/uploads/GenICam_Standard_v2_1_1.pdf)
3. **Start and buffer allocation.** Determine the payload after feature configuration. Use the GenTL stream payload when the stream defines it, otherwise use the remote payload feature. Honor producer alignment and minimum buffer count. Prefer producer allocation where required and use aligned consumer storage only when the CTI supports announcing it. Apply `TLParamsLocked` where supported, register new-buffer events, announce and queue buffers, start the data stream, then issue remote `AcquisitionStart` in combined mode. Define rollback for every completed stage. If rollback fails, leave the stream handle recoverable through stop. Treat an acquisition command that fails after a possible device side effect as requiring cleanup.
4. **Receive and frame ownership.** Use `EventGetData` with a zero timeout for try and poll. Try and poll skip waiting for a new completion and return `IRIS_BUSY` on consumer contention. CTI calls can still contend on producer locks. One reader per stream makes cancellation and dispatch tractable. Never pass a null event-data pointer as a readiness probe because GenTL can consume the event. Track each delivered frame with a stream-bound token that prevents stale or duplicate release, including after restart. Release consumes a valid token even on a requeue failure. Retain the buffer for cleanup and transition the stream to a recoverable failure state so an undetected shrinking pool cannot persist. After stop, release retires the buffer without requeue. [GenTL 1.6, §§6.3.7.2 and 6.3.7.5](https://www.emva.org/wp-content/uploads/GenICam_GenTL_1_6.pdf)
5. **Stop and cleanup.** Publish the stopping state before interrupting the reader. Coordinate with the active reader and any inline handler before unregistering events, flushing or revoking buffers. `EventKill` can abort the next event read even when no reader is currently waiting, so clear that state before restart. Attempt host stop even if the remote stop fails. Track each unfinished stage for retry. Keep outstanding images mapped until release, and keep the stream, device, interface and CTI alive until revocation is safe. An application-level stop deadline needs separate design because a vendor control call may block. [GenTL 1.6](https://www.emva.org/wp-content/uploads/GenICam_GenTL_1_6.pdf)
6. **Image bounds and clocks.** Check the reported image offset, dimensions, packing, padding and extent against both filled bytes and announced capacity using overflow-safe arithmetic. Expose stride only when its derivation is established. A valid payload containing one supported image can expose its image span with trailing chunk data excluded. Incomplete, unsupported and invalid images still carry a release obligation and expose no pixel pointer. Producer nanoseconds and host monotonic retrieval time have different meanings. Use the validity bits and never substitute one for the other. [GenTL 1.6 buffer information](https://www.emva.org/wp-content/uploads/GenICam_GenTL_1_6.pdf)
7. **Polling and diagnostics.** Preallocate acquisition bookkeeping and scratch at start. The normal receive and release paths must allocate zero heap memory from the first call, including timeout, empty queue and incomplete or rejected image. Qualify producer allocations separately. The poll limit counts delivered completions, including incomplete ones, and bounds visits to the handler. Return the count even when a later receive or release fails. Use typed status returns across the ABI. Capture the native error immediately before another producer call can overwrite it. Define a per-thread diagnostic and separate counters for consumer observations. Transport loss counters and frame-ID gaps have different semantics.
8. **Later Julia wrapper.** Mirror the fixed C layouts with isbits structs and verify offsets against C. Copy discovery strings before closing the list. Wrap device and stream handles with explicit `close` and keep parent objects rooted. Use a `with_frame` API that releases in `finally`, plus an explicit frame handle for advanced use. A borrowed Julia view must remain within its frame lifetime. Map row stride, packing and byte order explicitly before presenting a typed image. Julia can implement its polling loop with `try_get_frame` and no callback trampoline. A direct blocking C call occupies a Julia thread, so choose a scheduling strategy for timed waits and copy thread-local error details before yielding or switching OS threads. Use a package artifact or JLL for the consumer and its permitted GenApi runtime, with vendor CTIs selected at deployment.
9. **Consumer scope.** Iris covers discovery, GenApi feature access, and acquisition through the GenTL data stream. Qualify each CTI and acquisition configuration separately before relying on it in production.

## Verification before a stable release

The draft passed strict C11 and C++17 syntax checks. A temporary C shared library exported sizeof and offsetof probes. Julia 1.13.3 called those probes through @ccall and matched every field offset and size for all nine public structures on this host.

- Check the C ABI on each supported platform. Julia wrapper verification belongs to the later binding task.
- Verify the [allocation gate](IMPLEMENTATION_PLAN.md#acquisition-allocation-gate) and zero-timeout try and poll behavior.
- Use triggered mock and continuous simulator to test ordered feature configuration, software triggering, timeout, cancellation, held frames, stale tokens, bounded polling and restart. Inject failures at startup, requeue, stop and revoke. Exercise discovery while a separate device is streaming and stop one of two devices sharing a producer. Also acquire from triggered mock and continuous simulator simultaneously in one context, then repeat with capture producer and triggered mock on the bench.
- Qualify hardware by CTI, transport, and device configuration. Record frame bytes, metadata, feature readback, drops, latency, and jitter. Include external triggering and sustained multi-camera acquisition where applicable.
- Confirm the deployment toolchain and GenApi distribution terms using the local EMVA SDK and runtime archives. Use a separate runtime package or manifest for the CTIs and their drivers. ## Naming and ABI decisions

The GenTL hierarchy supplies `interface_id`, `device_id`, stream, module, frame ID and pixel format namespace. GenApi supplies node map, feature types, access, enum symbols, increment modes and command execution. The consumer owns frame borrows, receive statuses, timeouts and counters. Aeron's work limit supplies the callback polling convention. `iris_` is the Iris GenTL library prefix. The header keeps SDK handles private and uses fixed-width integer status and type values for FFI. Public declarations and layouts may evolve during development.

## Implemented GenTL and GenApi capabilities

- **Feature access.** Iris supports typed scalar and register access, GenApi text conversion, ordered feature batches, native write stacking, and per-device remote XML overrides. Feature browsing includes categories, selector relationships, flat filters, aliases, event IDs, and source inspection.
- **Events.** Iris can poll remote and module events and capture snapshots of the raw payload, decoded GenApi values, and available timestamps. Feature invalidation can be explicit or driven by producer events.
- **Frame payloads.** Iris accepts caller-owned host memory through `DSAnnounceBuffer` and exposes bounded multipart and contiguous GenDC part views. Named chunk values use the remote GenApi XML with transport chunk descriptors or one GenDC chunk metadata part. Direct DMA-BUF import, device-only GPU memory, and partial DMA delivery remain outside the current capture API.

The triggered native-ring mock requires an explicit count matching its four slots and producer-announced buffers. Iris writes `TLParamsLocked` before announcement and clears it after revocation. The mixed simulator test qualifies software-triggered native-ring capture and restart with frame borrows. The software-trigger example uses the triggered copy path.
